# Phase4 · думающий граф: активация вместо реактивного поиска

## Что именно сделано

Переход от «реактивного» поиска к «проактивной» памяти. Раньше память отвечала
на вопрос: *что похоже на запрос?* Теперь она отвечает ещё и на другой:
*что должен влиять на вывод сейчас?*

Разделение этих двух вопросов — центральная идея
[Activation-Guided Graph Retrieval for Cognitive Memory Reconstruction](https://arxiv.org/html/2611.13127v1)
(AGGR, ноябрь 2026). У нас оно реализовано поверх собственного append-only
журнала, а не поверх Neo4j:

| AGGR | Здесь |
|---|---|
| query-conditioned candidate selection | `Stage 1`: LSH ∪ Vector → RRF |
| activation-conditioned availability | `activation.availability()` + `σ` отношения |
| fan-aware traversal | `activation.run(fanout=4)` |
| recursive cues | вектор `goal` участвует в `m(c, e)` |
| typed evidence graph | `Thought.path` с `source` и `relation` |
| reinforcement | `triplex_feedback` → `journal.reinforce` |

## Модель

Граф `G = (V, E)` уже есть: сущности — узлы, факты — рёбра с `(s, r, o)`,
источником, confidence и битемпоральностью.

Кью момента:

```
c = embed(query + goal)
```

Активация факта (синапса):

```
boost(t) = boost₀ · 0.5^(age / 600 c)      # подкрепление затухает за ~10 мин
w(e) = confidence(e) · decay(e) · (1 + min(0.30, 0.12·ln(1 + access + 0.5·boost(t))))
                     · ontology_prior(r) · (0.4 + 0.6·cos(e, c))
```

Распространение импульса:

```
A[t+1] = B( δ·A[t] + η·Σ w(e)·m(c, e)·A[t] / √fan(v) )
B      = top-k + порог + ограничение веера
δ      = 0.55      η = 0.45      fanout = 4
```

`m(c, e)` — косинус отношения с активной целью. Поэтому при смене `goal`
тот же граф порождает другую мысль: направление задаётся не только текстом
вопроса.

`Thought` — не один вектор и не один факт, а траектория:

- `steps` — снимки фронта активации по шагам;
- `activation` — веса фактов на последнем шаге;
- `path` — путь от seed-факта к наиболее активированному, с источниками;
- `facts` — расшифровка в тексте для агента и интерфейса.

## Обратное распространение оценки

После того как агент проверил мысль, он вызывает:

```
triplex_feedback(fact_ids=thought.path, valence=+1 / -1,
                 thought_id=thought.thought_id)
```

Это **не градиентный спуск и не обучение модели**. Это обратное кредитование
по пути: последний факт получает максимальный вклад, seed — минимальный, вклад
затухает как `0.7^distance`. Результат пишется отдельным полем `boost` в журнал и не
трогает `access_count` (инвариант I10). В журнале лежит исходный `boost` и время
последнего подкрепления `boost_at`; в весе ребра участвует уже затухшее значение,
поэтому один удачно подкреплённый факт не становится постоянным лидером. Вклад
`boost` в `usage` ограничен и меньше вклада реальных обращений.

Ограничение намеренное: у нас нет дифференцируемой модели графа и размеченной
ошибки для неё. Честное оценочное подкрепление даёт проактивность без обмана.

## Инструменты

- `triplex_think(query, goal, k, steps)` — пустить импульс и получить мысль.
- `triplex_feedback(fact_ids, valence)` — подкрепить или ослабить путь.
- `triplex_search(..., goal, activate=True)` — обычный поиск теперь тоже
  пускает поток; `activate=False` возвращает старый BFS.
- `memory_search` в чате теперь отдаёт модели не только факты, но и компактный
  «Путь мысли»: цель, звенья с активацией и `doc_id`. Агент рассуждает вдоль
  активированного пути, а не только по релевантности.
- `triplex_graph()` — ребра получили `weight`, `boost` и `activation`;
  интерфейс подсвечивает ребра под током.
- `POST /api/memory/think` — тот же импульс для веб-интерфейса. В панели
  «Карта нейронов» есть форма «вопрос + цель → Пустить импульс»: она вызывает
  endpoint и сразу перезагружает граф, поэтому подсветку видно без чата.
  Граф отдаёт `thought.path` (id фактов), поэтому интерфейс рисует **путь мысли**
  золотым с подсвеченными узлами, а неактивные связи размывает и гасит.
  След мысли **угасает**: полураспад активации 15 с, полная очистка при
  активации < 0.02. Поэтому подсветка не зависает после того, как импульс
  прошёл. `boost` при этом остаётся в журнале — затухает только слепок тока.

`boost` и `activation` — разные вещи: `boost` сохраняется в журнале,
`activation` — слепок конкретного импульса в памяти процесса.

## Изоляция thoughts и границы обратной связи

След мысли хранится не одной переменной на всю память, а по ключу `scope`:
MCP использует `mcp:<user_id>`, веб-интерфейс — `web:<user_id>`, инструмент
`memory_search` в чате след не сохраняет (`remember_thought=False`) и поэтому не
перезаписывает мысль, пущенную пользователем. В `triplex_think` и `triplex_search`
возвращается `thought_id` (по умолчанию); `triplex_feedback` принимает только факты из этой
мысли (или из последней мысли в том же `scope`). Чужой факт отвергается с
`status: error`. Локальные вызовы `feedback()` без `scope` сохраняют старое
поведение для регрессий.

Кэш смежности ключуется составом актуальных фактов, а не только `generation`
журнала: при одном и том же `generation` разные `as_of` и архивация дают разные
графы. Дополнительно BFS проверяет каждый факт на принадлежность текущему срезу
`by_id` — старый факт из кэша больше не вызывает `KeyError`.

## Phase4+ · что улучшено (P0 + P1)

Первая версия Phase4 была однопутной и короткоживущей. Добавлено поверх того же
append-only журнала, без обучения модели:

1. **Цель участвует в отборе seeds.** `split_goal()` детерминированно разбивает
   цель на подцели; каждая подцель даёт свой кью-вектор, добавляет кандидатов
   через LSH/косинус и влияет на вес seed-факта. Раньше `goal` менял только
   косинус отношения на поздних шагах — если seed был не тот, путь уже не спасти.
2. **Адаптивный бюджет.** `plan_budget()` увеличивает число шагов для сложной
   цели и сужает `top_k/fanout` для маленького графа; значения остаются в границах
   старого импульса, так что старые вызовы детерминированы.
3. **Многопутевая мысль.** Вместо одного `path` мысль возвращает `paths` и
   `alternatives`: пути строятся из запасных родителей и соседних по активации
   концов. `path` остаётся первым для совместимости с интерфейсом и feedback.
   Появились `open_questions` (звенья, отсечённые бюджетом) и `conflicts`
   (два активных объекта у функционального отношения).
4. **Журнал мыслей.** `thoughts.jsonl` рядом с `journal.jsonl`: `triplex_think`
   пишет снимок (`goal`, `subgoals`, `paths`, `outcome`), `triplex_feedback` —
   событие с исходом. `triplex_thoughts` и `triplex_reflect` читают историю после
   перезапуска. Живой след для подсветки по-прежнему держится ~15 с и угасает.
5. **Структурированная обратная связь.** Старый вызов `fact_ids + valence`
   работает как раньше. Новый принимает `verdicts=[{fact_id, valence, reason}]`
   и `outcome`. Причины `good`, `irrelevant`, `outdated`, `wrong_relation`,
   `missing_link`, `contradiction` меняют не только `boost`, но и штраф отношения,
   надёжность источника и флаг спорного факта. Проверка допускает факт из любого
   пути мысли, а не только из лучшего; `access_count` не трогается (I10).
6. **Автоописание сервера.** `pulsenet_guide` строит каталог из реестра
   инструментов, а не из ручного списка, поэтому новые инструменты не теряются.
7. **Измеримая база.** `python eval/eval_phase4.py` печатает `path_hit@5`,
   `goal_sensitivity`, `false_activation_rate`, `feedback_gain`, `scope_leak`
   и `determinism` на синтетическом графе с известным ответом.

## Что сознательно НЕ реализовано

- Graph Transformer / message passing с обучаемыми весами — нет обучающих данных.
- Настоящий backprop — нет дифференцируемой функции потерь.
- Постоянный «поток consciousness» — память не должна гореть без запроса.
- Замер качества на реальных пользовательских данных: baseline на синтетическом
  графе есть (`python eval/eval_phase4.py`), но перенести его на живые запросы
  ещё предстоит; «умнее» по-прежнему не заявлено как измеренный на практике результат.
- Вектор мысли `z` как замена пути — путь сохранён, потому что он проверяем.

Это foundation Phase4: граф уже не просто хранит и ищет, а собирает мысль
под текущую цель и учится на её исходе.
